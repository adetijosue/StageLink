Help me to debug the attached sql snippet which gives the following error:

Failed to run sql query: ERROR: 42601: syntax error at or near "EXISTS" LINE 7: ALTER PUBLICATION supabase_realtime DROP TABLE IF EXISTS public.posts; ^

-- 1. Reload the schema cache to fix "schema cache" errors...

Why you’re getting syntax error at or near "EXISTS"

In PostgreSQL, the ALTER PUBLICATION ... DROP TABLE syntax does not support IF EXISTS.

So this line is invalid:

SQL Query

ALTER PUBLICATION supabase_realtime DROP TABLE IF EXISTS public.posts;

That’s why the parser complains right at EXISTS.

Fix: use DROP TABLE without IF EXISTS (or wrap in exception)

You have two practical options:

Option A (recommended): wrap each DROP/ADD in a DO $$ ... $$; block

This avoids failing if the table isn’t currently in the publication.

SQL Query

-- Reload schema cache (optional)
NOTIFY pgrst, 'reload schema';

BEGIN;

DO $$
BEGIN
  ALTER PUBLICATION supabase_realtime DROP TABLE public.posts;
EXCEPTION WHEN undefined_object THEN
  -- table isn't in the publication (or doesn't exist); ignore
  NULL;
END $$;

DO $$
BEGIN
  ALTER PUBLICATION supabase_realtime DROP TABLE public.post_likes;
EXCEPTION WHEN undefined_object THEN
  NULL;
END $$;

DO $$
BEGIN
  ALTER PUBLICATION supabase_realtime DROP TABLE public.post_comments;
EXCEPTION WHEN undefined_object THEN
  NULL;
END $$;

DO $$
BEGIN
  ALTER PUBLICATION supabase_realtime DROP TABLE public.messages;
EXCEPTION WHEN undefined_object THEN
  NULL;
END $$;

DO $$
BEGIN
  ALTER PUBLICATION supabase_realtime DROP TABLE public.chat_states;
EXCEPTION WHEN undefined_object THEN
  NULL;
END $$;

DO $$
BEGIN
  ALTER PUBLICATION supabase_realtime DROP TABLE public.profiles;
EXCEPTION WHEN undefined_object THEN
  NULL;
END $$;

DO $$
BEGIN
  ALTER PUBLICATION supabase_realtime DROP TABLE public.stories;
EXCEPTION WHEN undefined_object THEN
  NULL;
END $$;

DO $$
BEGIN
  ALTER PUBLICATION supabase_realtime DROP TABLE public.story_likes;
EXCEPTION WHEN undefined_object THEN
  NULL;
END $$;

DO $$
BEGIN
  ALTER PUBLICATION supabase_realtime DROP TABLE public.story_views;
EXCEPTION WHEN undefined_object THEN
  NULL;
END $$;

COMMIT;

BEGIN;

DO $$ BEGIN ALTER PUBLICATION supabase_realtime ADD TABLE public.posts; EXCEPTION WHEN duplicate_object THEN NULL; END $$;
DO $$ BEGIN ALTER PUBLICATION supabase_realtime ADD TABLE public.post_likes; EXCEPTION WHEN duplicate_object THEN NULL; END $$;
DO $$ BEGIN ALTER PUBLICATION supabase_realtime ADD TABLE public.post_comments; EXCEPTION WHEN duplicate_object THEN NULL; END $$;
DO $$ BEGIN ALTER PUBLICATION supabase_realtime ADD TABLE public.messages; EXCEPTION WHEN duplicate_object THEN NULL; END $$;
DO $$ BEGIN ALTER PUBLICATION supabase_realtime ADD TABLE public.chat_states; EXCEPTION WHEN duplicate_object THEN NULL; END $$;
DO $$ BEGIN ALTER PUBLICATION supabase_realtime ADD TABLE public.profiles; EXCEPTION WHEN duplicate_object THEN NULL; END $$;
DO $$ BEGIN ALTER PUBLICATION supabase_realtime ADD TABLE public.stories; EXCEPTION WHEN duplicate_object THEN NULL; END $$;
DO $$ BEGIN ALTER PUBLICATION supabase_realtime ADD TABLE public.story_likes; EXCEPTION WHEN duplicate_object THEN NULL; END $$;
DO $$ BEGIN ALTER PUBLICATION supabase_realtime ADD TABLE public.story_views; EXCEPTION WHEN duplicate_object THEN NULL; END $$;

COMMIT;

NOTIFY pgrst, 'reload schema';

Notes

  • undefined_object covers cases where the object/table isn’t present for that DROP.
  • duplicate_object covers cases where the table is already in the publication for that ADD.

Option B: pre-check publication membership (more complex)

You can query pg_publication_tables / pg_publication and generate only the needed DROP/ADD. This is longer, but avoids exception handling.

Quick validation questions (so I can tailor the exact script)

  2. Are you sure all these tables exist in public? (e.g., public.story_views)
